# XLS-Аналитика: графики и сводные таблицы из Excel-выгрузок

## Why

Боль у целевых сотрудников: они регулярно получают выгрузки в Excel, но ручной анализ отнимает часы — чистка данных, сведение листов, построение графиков; ошибки в формулах и расходящиеся версии файлов создают путаницу. Возможность, которую открывает сужение источника данных до файлов XLS/XLSX: приложение не требует интеграций и доступов к базам, а значит работает локально или в закрытом контуре. Это **боль к решению** с опорой на **возможность автономности**: лёгкое веб-приложение, где загрузка файла сразу даёт наглядные графики и сводные таблицы без ручной обработки, сокращая подготовку отчёта в 3–5 раз. Целевая аудитория — менеджеры, работающие с выгрузками из CRM/1С/ERP; аналитики, проверяющие гипотезу по свежему файлу; руководители, которым нужен простой дашборд по загруженным данным.

## Capabilities

- **CAP-1 — Загрузка файла**
  - **intent:** Пользователь может загрузить файл XLS/XLSX — через выбор файла или drag-and-drop, включая файлы с одним или несколькими листами.
  - **success:** Корректный многостраничный файл загружается, и его листы доступны для дальнейших шагов; недопустимый или повреждённый файл отклоняется с конкретным сообщением об ошибке, без остаточного частичного состояния.

- **CAP-2 — Валидация структуры**
  - **intent:** Приложение проверяет структуру загруженного файла — наличие обязательных колонок (эталонный набор B–G по образцу, см. `data-input-rules.md`), типы данных и пропуски — и сообщает о проблемах до построения аналитики.
  - **success:** При отсутствии обязательной колонки приложение называет именно её; файл без нарушений структуры проходит валидацию без действий пользователя.

- **CAP-3 — Предпросмотр и выбор листа**
  - **intent:** Пользователь видит предпросмотр первых строк выбранного листа и может переключиться на любой лист файла.
  - **success:** Первые строки выбранного листа отображаются в пределах лимита «до первого графика < 1 минуты» (см. `success-metrics.md`); переключение листа обновляет предпросмотр.

- **CAP-4 — Автоопределение типов колонок**
  - **intent:** Приложение автоматически определяет тип каждой колонки — число, дата, текст — без ручной настройки пользователем.
  - **success:** Типы колонок определяются корректно для ≥80% типовых файлов без вмешательства пользователя (см. `success-metrics.md`).

- **CAP-5 — Фильтры**
  - **intent:** Пользователь может фильтровать данные по дате и категории; фильтры применяются ко всем представлениям данных.
  - **success:** После применения фильтра графики и таблица отражают отфильтрованное подмножество; фильтр можно снять.

- **CAP-6 — Визуализация**
  - **intent:** Пользователь может построить по загруженным данным линейный, столбчатый и круговой графики, а также сводную таблицу.
  - **success:** Для одного выбранного набора данных пользователь переключает представление между указанными типами; каждый график соответствует текущему отфильтрованному набору.

- **CAP-7 — Экспорт результата**
  - **intent:** Пользователь может выгрузить результат в PNG, PDF или обратно в XLSX.
  - **success:** График экспортируется в PNG/PDF, данные — в XLSX; экспортированный артефакт соответствует текущему выбору на экране.

## Constraints

- Единственный источник данных — файлы XLS/XLSX; никаких интеграций, API, доступов к базам и других форматов.
- Данные не обновляются автоматически: приложение не подключается к живым источникам, актуализация возможна только повторной загрузкой файла.
- Обработка выполняется **локально на устройстве пользователя** (в браузере); файлы не покидают устройство — это исключает серверное хранение/передачу файлов.
- Лимит обработки — **30 000 строк суммарно по всем листам файла** (трактовка «на файл», см. Assumptions); файлы сверх лимита отклоняются с явным сообщением о превышении.
- Формулы Excel показываются **как есть** — сохранённые значения ячеек, без пересчёта (правила — в `data-input-rules.md`).
- Парсер обязан корректно обрабатывать нестабильность формата XLS: объединённые ячейки, лишние строки заголовков, скрытые листы (правила — в `data-input-rules.md`).
- Совместная работа в реальном времени не требуется: архитектура не обязана поддерживать многопользовательские сессии.
- Язык интерфейса — русский.
- Время от загрузки до первого графика — менее 1 минуты: сквозной лимит сценария, исключающий тяжёлую пакетную обработку и очереди.

## Non-goals

- Интеграции с CRM/1С/ERP, API-подключения и прямые доступы к базам данных.
- Автоматическое обновление данных / подключение к live-источникам.
- Совместная работа в реальном времени и многопользовательские сессии.
- Ручное редактирование и «чистка» данных внутри приложения — файл потребляется как загружен; проблемы помечаются валидацией (CAP-2), а не правятся пользователем.
- Форматы ввода кроме XLS/XLSX (нет CSV, JSON и др.).

## Success signal

Сотрудник из целевой аудитории загружает свежую выгрузку и получает первый корректный график **менее чем за минуту, без ручных правок в ≥80% типовых файлов**; подготовка отчёта ускоряется **в 3–5 раз**; **70% целевых сотрудников** используют приложение не реже раза в неделю. Полный набор порогов — в `success-metrics.md`.

## Assumptions

- «3–4 типа графиков» интерпретированы как линейный, столбчатый, круговой + сводная таблица — так они перечислены в MVP-функционале источника.
- Ручное редактирование данных внутри приложения не предполагалось (в перечне MVP отсутствует) — вынесено в Non-goals.
- Порог «< 1 минуты» трактуется как сквозной лимит пользовательского сценария, ограничивающий архитектурные решения.
- Лимит обработки «30 000 строк» трактуется как «на файл»; ограничение на отдельный лист не задавалось.
- Набор обязательных колонок (B–G) зафиксирован по единственному образцу выгрузки; для файлов иной структуры набор может уточняться по мере появления новых примеров.
