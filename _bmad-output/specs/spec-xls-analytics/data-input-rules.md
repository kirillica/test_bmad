# Правила обработки XLS-файлов — XLS-Analytics

Правила для контракта `SPEC-xls-analytics`, цитируются из Capabilities и Constraints.

## Допустимый вход

- Единый шаблон: одинаковый порядок обработки правил применяется ко всем XLS-файлам (единый набор правил, «единый шаблон» из источника).
- Только форматы **XLS** и **XLSX** (CAP-1).
- Один файл за сессию; внутри файла — один или несколько листов.
- Файл попадает в приложение через выбор файла или drag-and-drop.
- Обработка выполняется локально на устройстве пользователя; файлы не покидают устройство.
- Лимит — **30 000 строк суммарно по всем листам файла**; файлы сверх лимита отклоняются с явным сообщением. (Трактовка «на файл»: ограничение на отдельный лист не задавалось.)

## Эталонная схема (по образцу «Новый документ от 08.10.2026.xlsx»)

Образец — выгрузка отслеживания задач с трудозатратами: 1 видимый лист, 676 строк × 9 колонок, без объединённых ячеек, формул и скрытых листов. Заголовок — строка 1. Из 676 строк файла **627 — данные**, **49 — служебные строки-маркеры** (заполнена только колонка «Эпик»).

| Колонка | Встреченный тип | Заполнено (из 627 строк данных) | Статус в проверке CAP-2 |
|---|---|---|---|
| A «Эпик» | текст | 605 | рекомендуемая |
| B «Тип задачи» | текст (Задача / Подзадача / Баг / История) | 627 | **обязательная** |
| C «Задача» | текст | 627 | **обязательная** |
| D «Статус» | текст (Закрыт / Открыт / В работе и др.) | 627 | **обязательная** |
| E «Исполнитель» | текст | 627 | **обязательная** |
| F «Тип работы» | текст (Документация / Консультация / Обследование и др.) | 627 | **обязательная** |
| G «Затрачено времени (ч)» | число (0.5…176) | 627 | **обязательная** |
| H «Оценка» | число (3…160) | 140 | необязательная |
| I «Осталось (ч)» | число (−101…117) | 121 | необязательная |

- Набор «обязательных колонок» зафиксирован по этому образцу (B–G); при выгрузках иной структуры набор может уточняться.
- **Служебные строки-маркеры** (значение только в колонке «Эпик»): детектируются как «лишние строки заголовков», пользователь предупреждается; из аналитики они исключаются после уведомления.
- **Фильтр по дате (CAP-5):** в образце колонок-дат нет; фильтр по дате доступен, только если загруженный файл содержит колонку, распознанную как «дата».

## Порядок обработки

1. **Загрузка (CAP-1):** файл читается, листы извлекаются. Недопустимый формат или повреждённый файл → конкретная ошибка без частичного состояния.
2. **Валидация структуры (CAP-2):** проверяется наличие обязательных колонок (эталонный набор B–G), типы данных и пропуски. Нарушение → пользователь получает указание на конкретную проблему (например, какая колонка отсутствует), аналитика не строится до исправления файла.
3. **Предпросмотр (CAP-3):** первые строки выбранного листа показываются пользователю; лист можно переключить.
4. **Автоопределение типов (CAP-4):** колонки классифицируются как **число, дата, текст**.
5. **Фильтрация и визуализация (CAP-5, CAP-6):** фильтры по дате/категории применяются ко всем представлениям; доступны линейный, столбчатый, круговой графики и сводная таблица.
6. **Экспорт (CAP-7):** PNG/PDF для графиков, XLSX для данных.

## Значения ячеек

- Формулы Excel показываются **как есть** — используются сохранённые в файле значения ячеек, без пересчёта формул.

## Нестабильные конструкции XLS (обязаны обрабатываться без сбоя)

- **Объединённые ячейки** — не должны приводить к потере данных или ошибке парсинга.
- **Лишние строки заголовков** — детектирование фактической шапки таблицы.
- **Скрытые листы** — не должны молча искажать аналитику.

**Политика для всех трёх конструкций: предупреждать пользователя, а не исправлять молча.** При обнаружении такой конструкции приложение показывает явное предупреждение; аналитика строится по данным, но расхождение не скрывается. Точная форма предупреждения уточняется на этапе UX-проектирования. Кейс «лишние строки заголовков» подтверждён образцом (49 служебных строк-маркеров в файле-эталоне, см. «Эталонная схема»).

## Пропуски данных

- Пропуски в колонках детектируются на этапе валидации (CAP-2) и сообщаются пользователю; политика «пропуск = пусто или ноль» фиксируется типом колонки, а не молчаливым решением приложения.
