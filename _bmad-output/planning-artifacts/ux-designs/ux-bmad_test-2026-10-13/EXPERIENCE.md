# XLS-Analytics — Experience Spine

> Опыт: браузерное веб-приложение для локального анализа XLS/XLSX. Один пользователь, стационарный браузер, обработка на устройстве. Язык интерфейса — русский. Пара контрактов: этот спин (как работает) + `DESIGN.md` (как выглядит; кросс-ссылки на токены вида `{colors.primary}`).

## Foundation

`[ASSUMPTION: стек — на этапе архитектуры; опыт не привязан к конкретному фреймворку.]` Реализация: клиентское SPA без серверного бэкенда; файл читается локально (File API), данные живут в памяти сессии. Состояние между сессиями не сохраняется — повторная загрузка файла каждый раз (по PRD §6.2). Один пользователь, без аккаунтов и прав.

## Information Architecture

Три поверхности + глобальная шапка. Возможности контракта распределяются без дублей:

| Поверхность | Доступ откуда | Назначение | Возможности SPEC |
|---|---|---|---|
| **U1 Загрузка** | Открытие приложения | Выбор файла XLS/XLSX (drag&drop / кнопка), локальная обработка, результат валидации структуры | CAP-1, CAP-2 |
| **U2 Данные** | Автоматически после успешной загрузки; вкладка «Данные» | Листы, предпросмотр строк, типы колонок, предупреждения | CAP-3, CAP-4 |
| **U3 Анализ** | Вкладка «Анализ» (после U2) | Фильтры, графики, сводная таблица, экспорт | CAP-5, CAP-6, CAP-7 |

**Шапка (все поверхности):** название продукта, пилюля текущего файла (имя, число листов), переключатель темы (светлая/тёмная), кнопка «Новый файл» (прогрессивно скрыта на U1 — там и так выбор файла). Возврат: «Новый файл» сбрасывает данные сессии с подтверждением.

**Переход между U2/U3** — вкладки, состояние фильтров при переключении сохраняется (не сбрасывается: пользователь фильтровал — не теряет).

## Key Flows

### Flow-1: Анна — свежая выгрузка в готовый отчёт *(главный сценарий, узел: U1 → U2 → U3)*

Анна открывает приложение, перетаскивает файл. Приложение валидирует: структура соответствует эталону, но обнаружены служебные строки-маркеры → **предупреждающий баннер** (не блокирует, не «чинит» молча). Она на вкладке «Данные» видит лист «Main sheet», предпросмотр первых строк и чипы типов колонок («Затрачено времени (ч)» — число). На «Анализ» применяет чипы-фильтры «Тип работы → Документация», смотрит столбчатый график трудозатрат по исполнителям, переключается на круговую по статусам, жмёт в карточке графика «Экспорт → PDF» и получает отчёт.

**Кульминация:** от файла до экспортированного отчёта — меньше минуты, без Excel и без страха за «грязные» данные.

**Ветвление (edge):** файл без обязательной колонки «Статус» → блокирующая ошибка на U1, называющая колонку; Анна чинит файл в Excel и перекидывает заново. Узел покрыт: предупреждать, а не молча исправлять.

### Flow-2: Олег — файл сверх лимита *(error path, узел: U1 → блок → повторная попытка)*

Олег загружает выгрузку на 45 000 строк. U1 показывает блокирующую ошибку с лимитом (30 000) и количеством строк файла; дроп-зона остаётся активной — он срезает строки в Excel и загружает снова.

## Core States

| Состояние | Где | Поведение |
|---|---|---|
| Пустое приложение | U1 | Дроп-зона по центру, текст-подсказка, поддержка XLS/XLSX |
| Загрузка файла | U1 | Переопределённый прогресс (индетерминированный) внутри зоны; отмена возможна |
| Валидация выполняется | U1 | Зона показывает «Проверка структуры…»; блокирующие поля неактивны |
| Успех валидации | U1 | Пилюля «Готово» + авто-переход на U2 |
| Предупреждения | U2 | Янтарный баннер (считать, не прятать: «Обнаружено 49 служебных строк — исключены из анализа»), действует до смены файла |
| Блокирующая ошибка | U1 | Красное сообщение: имя колонки / превышение лимита / повреждённый файл; подсказка следующего шага |
| Пустой лист | U2 | Заметка «Лист пуст», вкладка анализа блокирована для него |
| Фильтр без результатов | U3 | Пустое состояние с действием «Сбросить фильтры» |
| Экспорт | U3 | Карточка графика — «Экспорт…» → меню PNG / PDF; данные — XLSX; тост-подтверждение; пустая выборка — экспорт заблокирован |
| Смена файла | все | «Новый файл» → подтверждение «Текущие данные будут удалены» → U1 |

## Component Patterns *(поведенческие, визуал — в DESIGN.md)*

- **Drop-zone:** drag-over подсветка; перетаскивание не-XLS файла — отклонение с сообщением; клик по зоне — системный выбор файла.
- **Вкладки листов (U2):** выбор листа переключает предпросмотр; активный лист = источник данных для U3.
- **Чипы типов колонок:** показывают автотип (число/дата/текст); hover — «n непустых значений»; тип не редактируется (автоопределение по контракту), объяснение — тултип-хелп.
- **Баннер предупреждений:** не-блокирующий; не скрывается кнопкой (данные остаются под вопросом); снимается только новым файлом.
- **Чипы фильтров:** мультивыбор по категории, меню-дропдаун значений; секция «Дата» появляется только если в файле распознана колонка-дата (в эталонном образце её нет — секции нет, это ожидаемо); «Сбросить» — один клик.
- **View-switcher:** линейный/столбчатый/круговой/таблица; переключение не сбрасывает фильтры; представления строятся на текущем отфильтрованном наборе.
- **Графики:** тултипы значений; оси подписаны; тёмная/светлая тема применяется к графикам также (токены `chart-*`).
- **Экспорт:** у графика — PNG и PDF; у данных — XLSX; экспортируется текущее состояние экрана (с активными фильтрами).

## Accessibility Floor

- **Контраст:** WCAG 2.2 AA в обеих темах: текст ≥4.5:1, UI-элементы и графика ≥3:1. Токены `DESIGN.md` гарантируют это по построению.
- **Клавиатура:** все контролы достижимы Tab, активные состояния видны (фокус-кольцо 2px `{colors.primary}`), Esc закрывает оверлеи и меню; дроп-зона активируется Enter/Space.
- **Текстовая альтернатива графиков:** представление «Таблица» (view-switcher) дублирует данные графика — это и есть альтернатива для скринридеров; графики дополнительно получают заголовок-подпись.
- **Цвет:** палитра `chart-1…6` читается при дейтеранопии/протанопии; значения не кодируются только цветом (подписи, доли, маркеры линий).
- **Движение:** никакой существенной информации через анимации; уважать prefers-reduced-motion (переходы между представлениями — без анимации).
- **Указатели:** hit-area кликабельных чипов/кнопок ≥24px (в идеале 32px); мелкие зоны типов — тултипы, не клики.

## Voice and Tone

Русский, точный, без фанфар. Баннер/ошибка называет факт и следующий шаг.

**Do:**
- «Перетащите файл сюда или нажмите, чтобы выбрать (XLS, XLSX)».
- «Не найдена обязательная колонка „Статус" (B6 в шапке файла?)» — имя колонки всегда.
- «Обнаружено 49 служебных строк — исключены из анализа. Проверьте, что это ожидаемо.»
- «Файл превышает лимит 30 000 строк (45 120). Сократите выгрузку и загрузите снова.»
- «Тип колонки определён автоматически: 1 208 непустых значений, 3 даты.»

**Don't:**
- «Ой-ой, что-то пошло не так…» — причина всегда называемая.
- «Ура, файл загружен! 🎉» — успех подтверждается переходом, а не конфетти.
- Двойные отрицания и канцелярит: «не требуется наличие» → «колонка не обязательна».
- Требования к пользователю без объяснения: после блок-ошибки всегда есть «что делать дальше».
