# PRD: XLS-Analytics

*Рабочее название — подтвердить.*

## 0. Document Purpose

PRD для меня как единственного читателя и владельца: фиксирует, что я строю, для чего и как пойму, что получилось. Документ построен на контракте `SPEC-xls-analytics` (ядро в `_bmad-output/specs/spec-xls-analytics/SPEC.md`, правила файлов в `data-input-rules.md`, метрики в `success-metrics.md`) и разбивке на истории (`stories.yaml`) — PRD их детализирует, не дублирует. Терминология зафиксирована в §3 Glossary.

## 1. Vision

Личный инструмент: **браузерное веб-приложение**, куда я загружаю XLS/XLSX-выгрузку и **за минуту** получаю наглядные графики и сводные таблицы — без ручной чистки, сведения листов и построения диаграмм в Excel. Файл обрабатывается **локально на устройстве** и не покидает его — данные не уходят наружу, что важно для чувствительных выгрузок (трудозатраты, задачи, персональные данные исполнителей).

Почему важно: ручной анализ выгрузи из трекинга задач (эпики, задачи, статусы, трудозатраты) съедает часы и плодит версии файлов с разными «правдами». Приложение даёт единый шаблон обработки: одинаковые правила для любого XLS-файла, проверка структуры до аналитики, предупреждения вместо молчаливых искажений.

## 2. Target User

### 2.1 Jobs To Be Done

- **Функциональная:** загрузить свежую выгрузку и быстро получить графики и сводные по трудозатратам — без возни с Excel.
- **Эмоциональная:** не бояться «грязных» файлов — структура проверяется, проблемы называются, а не прячутся.
- **Контекстная:** закрытый контур / локальная работа — данные не покидают устройство.
- **Социальная** *(вторично)*: выгружать результат в PNG/PDF/XLSX, чтобы делиться отчётом.

### 2.2 Non-Users (v1)

- Команды, которым нужна совместная работа в реальном времени и многопользовательский доступ.
- Пользователи CSV/JSON/API-источников — только XLS/XLSX.

### 2.3 Key User Journeys

*Лёгкий scope-диал (hobby): одна UJ, сжатая формула.*

- **UJ-1.** Я, сотрудник с только что полученной выгрузкой трекинга задач, захожу в приложение, тащу файл на страницу, приложение валидирует структуру и предупреждает о служебных строках-маркерах, я выбираю лист, вижу предпросмотр и типы колонок, применяю фильтр «Тип работы = Документация», смотрю столбчатый график трудозатрат по исполнителям, переключаюсь на сводную таблицу по статусам и выгружаю всё в PDF. Реализуют FR-1…FR-7. **Edge case:** в файле отсутствует обязательная колонка «Статус» — приложение называет её до построения аналитики.

## 3. Glossary

- **Лист** — страница внутри XLS/XLSX-файла; в образце — «Main sheet».
- **Эпик** — колонка A эталонной схемы, крупная единица работы.
- **Тип задачи / Задача / Статус / Исполнитель / Тип работы / Затрачено времени (ч) / Оценка / Осталось (ч)** — колонки эталонной схемы образца (9 колонок, A–I).
- **Обязательные колонки** — эталонный набор B–G (Тип задачи, Задача, Статус, Исполнитель, Тип работы, Затрачено времени (ч)); отсутствие любой из них блокирует аналитику с именем колонки.
- **Служебная строка-маркер** — строка с заполненной только колонкой «Эпик» (в образце 49 из 676); исключается из аналитики после предупреждения.
- **Автоопределение типов** — классификация колонки как число / дата / текст.
- **Сводная таблица** — агрегация по выбранному разрезу (группировка × сумма «Затрачено времени (ч)»).

## 4. Features

### 4.1 Загрузка и валидация файла *(реализует UJ-1)*

**Description:** на стартовой странице — зона загрузки. Файл XLS/XLSX попадает через выбор файла или drag-and-drop, обрабатывается локально. Сразу после загрузки идёт валидация по эталонной схеме: обязательные колонки, типы, пропуски. Служебные строки-маркеры детектируются и показывают предупреждение. `[ASSUMPTION: предупреждение — текстовый баннер, форма уточняется в UX]`

**Functional Requirements:**

#### FR-1: Загрузка XLS/XLSX

Я могу загрузить файл формата XLS или XLSX (выбор файла или drag-and-drop); файл может содержать один или несколько листов.

**Consequences (testable):**
- Корректный многостраничный файл загружается, его листы перечисляются для выбора.
- Файл сверх лимита **30 000 строк** отклоняется с явным сообщением о превышении.
- Недопустимый/повреждённый файл отклоняется с конкретной ошибкой; частичного состояния после неудачи не остаётся.

#### FR-2: Валидация структуры

Я получаю проверку структуры до построения аналитики: наличие обязательных колонок (B–G), типов данных и пропусков.

**Consequences (testable):**
- При отсутствии обязательной колонки называется именно она (например, «Статус»).
- Служебные строки-маркеры (заполнена только «Эпик») обнаруживаются, показывается предупреждение, из аналитики они исключаются.
- Файл без нарушений проходит валидацию без действий с моей стороны.

### 4.2 Предпросмотр и типы колонок *(реализует UJ-1)*

**Description:** после загрузки — предпросмотр первых строк выбранного листа, переключение листов, автоопределение типов колонок (число/дата/текст).

**Functional Requirements:**

#### FR-3: Предпросмотр и выбор листа

Я вижу первые строки выбранного листа и могу переключиться на любой лист файла.

**Consequences (testable):**
- Первые строки выбранного листа отображаются; переключение листа обновляет предпросмотр.
- Время от загрузки до первого графика укладывается в 1 минуту (сквозной лимит сценария, см. §7).

#### FR-4: Автоопределение типов

Каждая колонка автоматически классифицируется как **число, дата или текст** без ручной настройки.

**Consequences (testable):**
- Типы определяются корректно для ≥80% файлов без моего вмешательства.
- Частично пустые числовые колонки («Оценка», «Осталось (ч)») классифицируются по большинству непустых значений.
- Распознанная колонка-дата активирует фильтр по дате (FR-5); в эталонном образце колонок-дат нет — фильтр не создаётся, это ожидаемое поведение.

### 4.3 Фильтры *(реализует UJ-1)*

**Description:** фильтры по категориям и дате применяются единовременно ко всем представлениям и снимаются без потери данных.

**Functional Requirements:**

#### FR-5: Фильтры по категориям и дате

Я могу отфильтровать данные по категориям (Статус, Тип работы, Тип задачи, Исполнитель, Эпик) и по дате — если загруженный файл содержит распознанную колонку-дату.

**Consequences (testable):**
- После применения фильтра графики и сводная таблица отражают отфильтрованное подмножество.
- Фильтр можно снять; данные не теряются.

### 4.4 Визуализация *(реализует UJ-1)*

**Description:** три типа графиков (линейный, столбчатый, круговой) и сводная таблица по загруженным/отфильтрованным данным; переключение представлений без сброса фильтров. Типовые разрезы — трудозатраты по Исполнителю, Типу работы, Статусу, Эпику. `[ASSUMPTION: интерактивность графиков минимальна — тултипы, без глубоких настроек]`

**Functional Requirements:**

#### FR-6: Графики и сводная таблица

Я могу построить по данным линейный, столбчатый и круговой графики и сводную таблицу.

**Consequences (testable):**
- Все четыре типа доступны для одного выбранного набора данных; переключение работает.
- Каждое представление соответствует текущему отфильтрованному набору.

### 4.5 Экспорт *(реализует UJ-1)*

**Description:** экспорт графика в PNG/PDF и данных в XLSX из текущего состояния экрана.

**Functional Requirements:**

#### FR-7: Экспорт результата

Я могу выгрузить результат: графики — в PNG/PDF, данные — в XLSX.

**Consequences (testable):**
- Экспортированный артефакт совпадает с текущим выбором на экране (включая активные фильтры).

**Feature-specific NFRs (сквозные):**
- **Локальность (безопасность):** файл и все промежуточные данные обрабатываются только на устройстве; никаких сетевых отправок содержимого файла. (FR-1)
- **Производительность:** сквозной путь «загрузка → первый график» < 1 минуты. (FR-1, FR-6)
- **Язык:** интерфейс на русском языке. (все FR)

## 5. Non-Goals (Explicit)

- Интеграции с CRM/1С/ERP, API-подключения, прямые доступы к базам.
- Автоматическое обновление данных / live-источники.
- Совместная работа в реальном времени, многопользовательские сессии.
- Ручное редактирование и «чистка» данных внутри приложения.
- Форматы ввода кроме XLS/XLSX (нет CSV, JSON и др.).

## 6. MVP Scope

### 6.1 In Scope

- Загрузка XLS/XLSX (выбор файла / drag-and-drop), несколько листов.
- Валидация структуры по эталонной схеме (B–G) + предупреждение о служебных строках-маркерах.
- Предпросмотр первых строк, выбор листа, автоопределение типов.
- Фильтры по категориям (и дате — при наличии колонки-даты).
- Линейный, столбчатый, круговой графики и сводная таблица.
- Экспорт: PNG/PDF (графики), XLSX (данные).
- Обработка локально на устройстве, UI на русском.

### 6.2 Out of Scope for MVP

- Какие-либо другие форматы файлов (CSV, JSON) — причина: только XLS/XLSX в контракте.
- Сохранение состояния между сессиями и история загрузок — `[ASSUMPTION: повторная загрузка файла каждый раз, согласуется с «нет автообновления данных»]`.
- Мобильная адаптация — `[ASSUMPTION: оптимизация под стационарный браузер; мобильная версия не приоритетна]`.

## 7. Success Metrics

*Источник: `success-metrics.md` контракта. Валидируют FR-1…FR-7.*

- **SM-1:** Время от загрузки до первого графика **< 1 минуты**. (FR-1, FR-6)
- **SM-2:** Доля файлов, распознанных без ручных правок, **> 80%**. (FR-2, FR-4)
- **SM-3:** Регулярное использование: **не реже раза в неделю** (для личного инструмента — «не забрасываю через месяц»). (все FR)
- **SM-4:** Подготовка типового отчёта **в 3–5 раз быстрее**, чем в Excel. (все FR)

- §4.1 (FR-2): форма предупреждения — текстовый баннер, детали в UX.
- §4.4 (FR-6): интерактивность графиков минимальна (тултипы), без глубоких настроек.
- §6.2: без сохранения состояния между сессиями (повторная загрузка файла).
- §6.2: оптимизация под стационарный браузер; мобильная адаптация не приоритетна.
- Набор обязательных колонок (B–G) зафиксирован по единственному образцу; при других структурах выгрузок набор уточняется.
- Контри-метрики для hobby-версии не вводятся.
